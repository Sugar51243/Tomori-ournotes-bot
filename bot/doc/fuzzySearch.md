# 模糊搜索机制

实体端点（乐团 / 歌曲·谱面 / 角色 / 卡片 / 活动 / 卡池 / 贴纸）传入 `text` 时，服务把这段文字解析成实体再出图。本文只讲机制，各端点的请求参数见 [endpoint.md](endpoint.md)。

## 一句话

文字 → 查别名索引 → 按 **ID > 自信息 > 关联** 解析成实体 → 多命中出该种类的**列表图**，唯一命中出**单查结果**。

## 别名索引

- 每个游戏区域各一份，由该区域的 master 数据构建，按「区域 + dataVersion」缓存在磁盘（游戏更新后自动重建）。
- 收录对象：乐团、歌曲、角色、角色卡、支援卡、卡池、活动、贴纸的名称，外加卡片属性（绯红/绀碧/…，含朴素颜色词与元素联想，见下）与歌曲等级。
- 多语言：一条名称会取四个区域的全部语言——日服文本表几乎没有中文，只按本区域取会让中文用户在日服搜不到曲目。
- 名称变体：忽略大小写、去掉标点（`MyGO!!!!!` 与 `mygo` 等价）。
- 用户关键词作为**独立覆盖层**并入索引，不写进磁盘缓存（见下方「用户关键词」）。

## 各端点可用的搜索维度

| 端点 | 自信息（实体自身） | 关联（其它类型 → 本实体） |
| --- | --- | --- |
| 乐团 `/searchBand` | 乐团名（多语言、忽略大小写与标点）、自定义关键词、乐团 ID | 角色名 → 该角色所属的乐团 |
| 歌曲 `/searchSong`、`/songChart` | 歌曲名、自定义关键词、歌曲 ID、等级（`lv26`）、歌曲 ID 范围（`25-30` / `<30` / `>30`）、乐曲属性（绯红 / 绀碧 / …） | 乐团名 → 该团曲目；角色名 → 所属乐团的曲目；活动名 → 活动曲与挑战曲 |
| 角色 `/searchCharacter` | 角色名（全名 / 短名 / 英文名）、自定义关键词、角色 ID | 乐团名 → 该团成员；活动名 → 活动的加成与相关角色 |
| 卡片 `/searchCard`、`/searchMemberCard`、`/searchSupportCard` | 卡名（含副标题）、稀有度（`4星` / `★4` / `r` / `sr` / `ssr` / `ex`）、卡片属性（绯红 / 绀碧 / …）、自定义关键词、卡片 ID | 角色名 → 该角色的卡；乐团名 → 该团角色的卡；活动名 → 活动卡与加成卡；卡池名 → 该卡作为 UP 的卡池 |
| 活动 `/searchEvent` | 活动名、活动 ID、加成属性（绯红 / 绀碧 / …）、状态词（进行中 / 未开始 / 已结束 / 即将结束）、日期串（`2026-09-30` / `2026-9-30` / `30-9-2026` / `2026/9/30`，月份 `2026/9`） | 乐团名 / 角色名 → 活动的加成字段；歌曲名 → 相关活动；卡片名 → 相关活动；卡池名 → 相关卡池（启发式） |
| 卡池 `/searchGacha` | 卡池名、卡池 ID | 卡片名 → 该卡作为 UP 的卡池；角色名 / 乐团名 → 其名下卡片的 UP 卡池；活动名 → 相关卡池（启发式） |
| 贴纸 `/getStampImage` | 贴纸名、贴纸 ID（纯数字） | 角色名 → 归属角色的贴纸；团体名 → 该团体成员的贴纸；活动名 → 活动加成角色的贴纸 |

## 一次搜索怎么走

1. **ID**：纯数字直接按该端点的 ID 查询（如 `/searchSong` 的 `text:"100001"`）。
2. **自信息**：文字命中上表左侧任一维度时，只用自身维度，不再混入关联结果。
3. **关联**：自身没命中时，才用上表右侧的关系推导出本类型的结果（关系口径见 [src/db/relations.ts](../src/db/relations.ts)）。
4. **多命中 → 列表图，唯一命中 → 单查结果**：如 `/searchSong` 搜乐团名得到歌曲列表图，搜唯一歌名得到歌曲详情图。

> 数字 / 等级 / 日期这类**筛选项**在两条路上都保留，可与关联维度组合：`lv26 MyGO` = 该团的 26 级谱面。

**多参数 = 同时满足（AND）**：查询里的每个词都参与过滤，不会因为命中了其中一个就丢掉其它。
`nnk ssr` = 关键词 nnk（角色）的卡 ∩ SSR；`绯红 lv26` = 绯红属性 ∩ 26 级谱面。
只有「整条查询与某个乐团/角色名完全同名」（`MyGO`、`Ave Mujica`）才走整体同名短路、直接返回该实体。

## 匹配细则

- 按词匹配（空格、中英文引号分词）。
- **多参数同时生效**：每个词的约束都要满足 —— 索引命中的词走各自维度，索引没命中的词按子串在实体字段里找（如 `ssr` 命中 rarityLabel），两者一起 AND。
- **死词忽略**：谁都匹配不到的单个词（错别字、噪声）当作无用词丢掉，而不是把结果清空（`MyGO zzz` = 该团的卡）；但整条查询一个能命中的词都没有时返回空，不退化成"列出全部"。
- **已被"自身维度"解释的词不再重复作约束**：`mujica` 解析成乐团（该团的卡）后，不会再要求卡的名字里含 "mujica"。
- **稀有度是精确维度**：`sr` 得 SR、`ssr` 得 SSR、`ex` 得 EX，互不串味（若走子串，`'ssr'.includes('sr')` 会让 `sr` 把 SSR 一起捞出来）。星数写法 `4星` / `★4` 等价。
- **同名实体边界**：索引命中按类型合并成一份 id 列表，不保留"哪个词命中哪个实体"。若某实体的名字恰好等于查询里的另一个词（例如有一张留影卡的名字就叫 `Ave Mujica`，而查询是 `"Ave Mujica" 4星`），它会跟着被那个词命中而进入结果。
- **整体同名**：输入与某个乐团名 / 角色名 / 用户关键词完全相同时，直接按该名称的分类命中，不再分词——避免 `Ave Mujica` 被拆成 ave / mujica 误配 `unravel`。
- **子串回退**：索引没命中的词按子串在各端点自己的文本里找；关联维度同样适用（「アイの奔流」可命中「アイの奔流 atoz」）。
- **数字与关系串**：`lv26` 按歌曲等级；`25-30`、`<30`、`>30` 按歌曲 ID 范围；贴纸端点的纯数字按贴纸 ID。
- **属性词**：三类实体各按自己的属性字段命中 —— 活动按**加成属性**、歌曲按**乐曲属性**、卡片（成员卡与支援卡）按**卡片属性**；可与其它维度组合（`绯红 lv26` = 绯红属性的 26 级谱面）。同一属性认下列写法（结果完全等价）：
  - 官方名与变体：`绯红` / `紅赤` / `Ruby`、`绀碧` / `Azure`、`翡翠` / `Jade`、`琉金` / `山吹` / `Amber`、`紫苑` / `Violet`，以及「…属性 / …タイプ / … Type」整词。
  - 朴素颜色词：`红` / `紅`、`蓝` / `藍`、`绿` / `綠`、`黄` / `黃`、`紫`（简繁通用），英 `red` / `blue` / `green` / `yellow` / `purple`，日 `赤` / `青` / `緑`，韩 `빨강` / `파랑` / `초록` / `노랑` / `보라`。
  - 元素联想：`火` / `炎` → 绯红，`水` / `冰` → 绀碧，`草` / `木` / `森` → 翡翠，`光` / `雷` / `电` → 琉金，`暗` / `闇` / `影` → 紫苑。
  - 这些词是**索引里的别名**，因此优先于子串回退：搜 `水` 得到的是绀碧属性，而不是标题含「水」的歌。
- **活动专属**：`进行中` / `未开始` / `已结束` 等状态词、日期串。日期串按「时间窗口与活动起止区间重叠」过滤（按该服时区理解输入）：
  - 支持 `2026-09-30` / `2026-9-30` / `30-9-2026` / `2026/9/30` / `9/30/2026` 等写法（分隔符在一串内一致、可省略零填充）；月份 `2026/9` / `9/2026` 表示整个月。
  - 横杠的 `9-2026` 与歌曲 ID 区间冲突，按区间处理；`1-2-2026` 这类两种读法都合法的二义写法与不存在的日期（`2026-2-30`）不会命中任何活动。
- 自定义关键词与常规别名同权参与以上全部匹配。

## 用户关键词

`/keyword/upload`、`/keyword/delete`（需要数据库）可给**角色 / 角色卡 / 支援卡 / 歌曲 / 乐团**五类挂检索别名（活动、卡池、贴纸没有关键词）：

- **立即生效**：关键词作为内存覆盖层合并进索引，上传 / 删除后主动强刷，并让渲染缓存换代。
- **查重规则**：
  - 同一关键词可挂**同类型的多个实体**（两首歌共用一个别名允许，搜索会出多项列表）；
  - 不可**跨类型**共用（歌曲与角色不能共用同一个关键词）；
  - 不得与任何现存实体名 / 别名重合（含卡片属性、贴纸名）；
  - 同一实体不能重复；单个实体有关键词数量上限。
